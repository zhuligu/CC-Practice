01开篇词共生而非替代:极客与 AI 的共舞
整门课的导言,核心论点:Claude Code 与传统 AI 编程工具(Copilot/Cursor/Windsurf)的本质差异——不是更强的补全,而是工程化协作范式。AI 不会取代工程师,会用 AI 的工程师会取代不会用的。
02正课登高望远 · Claude Code 全景导览
技术栈全貌导览,核心目的是建立 Claude Code 的"心理地图"。Claude Code 不是一个产品,而是一套可扩展的工程体系:Skills / SubAgent / Hooks / MCP / Headless / SDK / Plugins 七大机制。
03正课过目不忘 · CLAUDE.md 记忆系统
记忆层第一讲,核心目的是把"Claude Code 没记忆,所以每次都从零开始"这个根本问题讲透。记忆系统由四个层级组成:用户级 / 项目级 / 本地级 / 规则目录,CLAUDE.md 是项目记忆的核心载体。
04正课分而治之 · 子代理核心概念
SubAgent 系列开篇,把"子代理"这个最容易被误解的概念讲透。子代理 = 一个带着"独立 system prompt + 独立工具权限 + 独立上下文窗口"的专职小助手,主对话是协调者,子代理是执行者。
05正课明察秋毫 · 只读型子代理实战
SubAgent 第 1 实战,聚焦"只读型子代理"——Claude Code 工程化里出场率最高的一类角色。code-reviewer 是"明察秋毫"的代表:只能看,不能改,但要看得准、看得快、看得全。
06正课守土有责 · 可执行型子代理实战
SubAgent 第 2 实战,聚焦"可执行型子代理"——以 test-runner 为代表。和"只读"相比,test-runner 多了一个高危工具 Bash,核心命题:怎么给 Bash 工具配 permission 白名单,在"能跑"和"安全"之间找平衡。
07正课越俎代庖 · 可写型子代理实战SubAgent 第 3 实战,聚焦"可写型子代理"——Claude Code 工程化里权限最高的子代理类型。前 3 讲都不改变状态,可写是第一个"会改变状态"的类别,一旦写错就回不去了,所以必须严控边界。
08正课并行不悖 ·SubAgent 第 4 实战,聚焦"多子代理协同"——前 3 讲是单兵作战,本讲讲团队作战:并行 + 流水线两种协同模式,主对话是协调者,文件传递状态,流水线门控失败重试,4 类典型编排场景。看典型案例。,流水线门控失败。

10正课触类旁通 · SKILL.md 结构与触发机制
Skills 系列开篇,把"Skills 是什么、怎么写、怎么触发"讲透。Skills 与 SubAgent 是 Claude Code 两种能力扩展机制,但触发方式截然不同:SubAgent 由主对话显式调起,Skills 由 LLM 推理自动发现。
11正课令行禁止 · 任务型 Skills 实战
讲"反向操作"——怎么让 Skill 禁止模型自动调用,只允许用户主动调。核心是 disable-model-invocation: true 这个 frontmatter 字段。3 类场景:团队 SOP / 危险操作 / 调试工具,共性是必须严格按步骤走。
12正课架构循序渐进 · 渐进式披露架构设计
深入到"为什么是 3 层而不是 1 层或 5 层"——这是 Skills 的 token 经济性核心命题。用财务分析 Skill 贯穿:目录页 + 章节 + 附录 3 层架构,如何把 token 利用率从 12% 提升到 95%+。
13正课组合浑然天成 · Skills 高级模式与 SubAgent 配合实战
进入"组合"——Skills + SubAgent + Commands 三件套不是孤立机制,而是可以联动的。3 种组合模式(注入 / 动态 / 流水线)+ 2 个实战(代码审查专家 / 部署专家)。
14正课全局登高望远 · Skills 架构定位与设计模式

15正课行业星火燎原 · Skills 出圈——从 Claude Code 到行业开放标准

17正课Hooks防微杜渐 · Hooks 事件驱动自动化(上)

💡 友情提示

⚠️ 不要跳读

本课程内容有强逻辑链(子代理→Skills→Hooks→MCP→Headless→SDK→Plugins),跳读会让你对前后依赖的概念产生理解断层。建议按编号顺序学。

⚠️ 不要只看不练

33 讲里超过 20 讲带实战代码或工程项目。只看代码不跑起来,收获不到 10%。

⚠️ 不要用默认配置上线

尤其 Hooks 与 Rules 章节提到的安全三件套,生产环境必须有;否则一旦 Claude 误删数据库就晚了。
